# 🏛️ Техническое задание (ТЗ) на разработку бэкенда
## Проект: «Словарь экономиста» (Economics Hub / SamSU Economics)

---

## 1. Введение и цели проекта

### 1.1. Текущее состояние
В настоящий момент проект «Словарь экономиста» работает как клиентское Single Page Application (React 19 + Vite):
* Все экономические термины хранятся локально в `localStorage` браузера пользователя.
* Пароль администратора (`samsueconomics`) жестко прописан на клиенте (`sessionStorage`).
* Любые термины, добавленные или отредактированные администратором, остаются только в его браузере и не попадают к студентам.

### 1.2. Цель бэкенда
Разработать надежный, легковесный и масштабируемый REST API сервер с реляционной базой данных:
1. **Единая централизованная база**: термины доступны всем студентам и преподавателям в реальном времени.
2. **Безопасная админка**: вход по логину/паролю с хешированием (`bcrypt`), авторизация по `JWT Bearer`.
3. **Серверный поиск и фильтрация**: по категориям, первой букве (алфавитная лента) и ключевым словам на 3-х языках (**RU**, **EN**, **UZ**).
4. **Тренажёр флеш-карточек**: выдача случайной перемешанной колоды терминов.
5. **Резервное копирование**: экспорт и импорт базы в JSON.
6. **Полная совместимость**: формат данных полностью повторяет существующую структуру текущего фронтенда React 19.

## 3. Модель данных (База данных)

### 3.1. Структура сущностей

#### 1. Таблица `users` (Администраторы)
* `id`: `UUID` (Primary Key, автогенерация).
* `username`: `VARCHAR(64)` (UNIQUE, NOT NULL) — логин администратора.
* `password_hash`: `VARCHAR(255)` (NOT NULL) — хеш пароля (`bcrypt`).
* `role`: `VARCHAR(32)` (DEFAULT `'admin'`).
* `created_at`: `TIMESTAMPTZ` (DEFAULT `NOW()`).

#### 2. Таблица `categories` (Разделы экономики)
* `id`: `VARCHAR(32)` (Primary Key) — `micro`, `macro`, `finance`, `econometrics`, `international`, `other`.
* `icon`: `VARCHAR(64)` — имя иконки Lucide (`Store`, `Globe`, `Landmark`, `TrendingUp`, `Compass`, `Sparkles`).
* `sort_order`: `INT` (DEFAULT 0).

#### 3. Таблица `terms` (Экономические термины)
* `id`: `VARCHAR(64)` (Primary Key) — строковый ID вида `t_gdp` или `term_1712345678_abcd`.
* `category_id`: `VARCHAR(32)` (Foreign Key -> `categories.id`).
* `is_published`: `BOOLEAN` (DEFAULT `true`).
* `views_count`: `INT` (DEFAULT 0).
* `created_at`: `TIMESTAMPTZ` (DEFAULT `NOW()`).
* `updated_at`: `TIMESTAMPTZ` (DEFAULT `NOW()`).

#### 4. Таблица `term_translations` (Локализованный контент)
* `id`: `UUID` (Primary Key).
* `term_id`: `VARCHAR(64)` (Foreign Key -> `terms.id` ON DELETE CASCADE).
* `lang`: `VARCHAR(4)` (NOT NULL) — `'ru'`, `'en'`, `'uz'`.
* `term`: `VARCHAR(255)` (NOT NULL) — название термина.
* `definition`: `TEXT` (NOT NULL) — академическое определение.
* `example`: `TEXT` (NULLABLE) — пример или математическая формула.
* *Индекс:* UNIQUE `(term_id, lang)`.

> 💡 **Упрощённый вариант:** Допускается хранение переводов внутри таблицы `terms` в одной колонке `translations JSONB` с полями `{ ru: {...}, en: {...}, uz: {...} }`. Это полностью идентично текущему формату фронтенда и сокращает количество связей (JOIN).

## 4. Спецификация REST API (`/api/v1`)

### 4.1. Публичные маршруты (Студенты и гости)

| Метод | Путь | Описание | Параметры / Тело |
| :--- | :--- | :--- | :--- |
| `GET` | `/terms` | Список терминов с фильтрацией | `?category=macro&search=ввп&letter=В&lang=ru&page=1&limit=50` |
| `GET` | `/terms/:id` | Детальная страница термина | Увеличивает `views_count` на +1 |
| `GET` | `/categories` | Список разделов со счётчиком терминов | Возвращает количество терминов по разделам |
| `GET` | `/flashcards` | Случайная колода для тренажёра | `?category=macro&limit=20` (рандомный порядок) |
| `GET` | `/stats/summary` | Статистика для шапки и футера | Общее кол-во, процент трёхъязычной полноты |

#### Формат ответа объекта термина:
```json
{
  "id": "t_gdp",
  "category": "macro",
  "dateAdded": "2026-10-01T10:00:00.000Z",
  "dateUpdated": "2026-10-01T10:00:00.000Z",
  "ru": {
    "term": "ВВП (Валовой внутренний продукт)",
    "definition": "Рыночная стоимость всех конечных товаров и услуг...",
    "example": "GDP = C + I + G + NX."
  },
  "en": {
    "term": "GDP (Gross Domestic Product)",
    "definition": "The total monetary or market value of all finished goods...",
    "example": "Calculated via expenditure approach: GDP = C + I + G + NX."
  },
  "uz": {
    "term": "YaIM (Yalpi ichki mahsulot)",
    "definition": "Mamlakat hududida maʼlum bir davr davomida ishlab chiqarilgan...",
    "example": "YaIM = C + I + G + NX."
  }
}
```

## 5. Требования к поиску и узбекскому языку (UZ)

* **Регистронезависимый поиск**: `ILIKE` или Trigram Index (`pg_trgm`).
* **Нормализация узбекских апострофов**:
  * В узбекской латинице буквы `O‘` и `G‘` часто вводятся разными символами: `'`, `’`, `` ` ``, `‘`, `ʻ`.
  * Бэкенд должен приводить все варианты апострофов к единому виду перед поиском, чтобы студент находил термин вне зависимости от раскладки.
* **Алфавитная навигация**:
  * Фильтрация `letter` проверяет первую букву названия на языке, указанном в `lang` (`ru` — кириллица, `en`/`uz` — латиница).

## 6. Безопасность

1. **Хеширование паролей**: `bcrypt` (10 раундов соли).
2. **CORS**: белый список адресов фронтенда (`http://localhost:5173`, прод-домен университета).
3. **Rate Limiting**: ограничение количества попыток входа на `/auth/login` (не более 5 попыток в минуту).
4. **Валидация**: проверка входящих JSON-данных перед записью в базу.

## 7. Развертывание (Docker Compose)

Бэкенд должен поставляться с `Dockerfile` и `docker-compose.yml`, содержащим контейнеры:
1. `db`: PostgreSQL 15 (с сохранением данных в Docker Volume).
2. `api`: Node.js / Express сервер.
3. Начальный сид (seed): автоматическое создание аккаунта администратора и загрузка стартовых 10 терминов при первом старте.
